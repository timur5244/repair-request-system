1.ПРОМПТ:
Создай веб-приложение на Laravel 10+ для системы приёма заявок в ремонтную службу. 

Требования к проекту:
- Использовать Laravel 10+
- База данных: SQLite (для простоты локального запуска)
- Аутентификация: упрощённая (выбор пользователя из списка или логин по имени)
- Структура: чистая архитектура с разделением на слои (модели, сервисы, контроллеры)

Создай следующую структуру:
1. Модель User с полями: name, email, password, role (dispatcher/master)
2. Модель Request (заявка) с полями согласно ТЗ:
   - clientName (string, required)
   - phone (string, required)
   - address (string, required)
   - problemText (text, required)
   - status (enum: new, assigned, in_progress, done, canceled)
   - assignedTo (foreignId to users, nullable)
   - timestamps (createdAt, updatedAt)

2.ПРОМПТ:
Добавь упрощённую систему аутентификации:

1. Создай страницу входа /login со списком всех пользователей (для простоты тестирования)
   - При клике на пользователя происходит вход без пароля
   - После входа редирект на соответствующую панель (диспетчер/мастер)

2. Создай middleware для проверки ролей:
   - dispatcher: доступ только для диспетчеров
   - master: доступ только для мастеров

3. Создай базовые шаблоны Blade:
   - layouts/app.blade.php (общий шаблон с навигацией)
   - components/ (для переиспользуемых компонентов)

4. Добавь страницу создания заявки (доступна для всех авторизованных):
   - Форма с полями: clientName, phone, address, problemText
   - После создания статус = new, assignedTo = null
   - Валидация всех полей

3.ПРОМПТ:
Реализуй панель диспетчера (/dispatcher/dashboard):

1. Главная страница со списком всех заявок:
   - Таблица с колонками: ID, клиент, телефон, адрес, статус, назначенный мастер, действия
   - Пагинация (по 10 записей)

2. Фильтрация заявок:
   - Фильтр по статусу (выпадающий список со всеми статусами)
   - Фильтр по мастеру (выпадающий список с мастерами)
   - Фильтры должны работать через GET-параметры

3. Действия над заявками:
   - Кнопка "Назначить мастера" (для статуса new):
     - Открывает модальное окно с выбором мастера
     - После назначения статус меняется на assigned
   - Кнопка "Отменить" (для статусов new, assigned, in_progress):
     - Меняет статус на canceled
     - Подтверждение действия

4. Сервис для бизнес-логики:
   - Создай RequestService с методами для обновления статусов
   - Внедри валидацию статусов (нельзя отменить уже done и т.д.)

4.ПРОМПТ:
Реализуй панель мастера (/master/dashboard) с защитой от параллельных запросов:

1. Главная страница мастера:
   - Список заявок, назначенных на текущего мастера (assignedTo = текущий пользователь)
   - Группировка по статусам (новые назначенные, в работе, выполненные)

2. Действия мастера:
   - Кнопка "Взять в работу" (для статуса assigned):
     - Переводит заявку в статус in_progress
     - Должна быть потокобезопасной
   - Кнопка "Завершить" (для статуса in_progress):
     - Переводит заявку в статус done

3. Защита от гонок (race condition):
   - Используй optimistic locking через поле version или timestamp
   - Или используй транзакции БД с блокировкой строк (SELECT FOR UPDATE)
   - При параллельных запросах на "Взять в работу":
     - Первый запрос успешен
     - Второй получает 409 Conflict с сообщением "Заявка уже взята в работу"

4. Тестирование:
   - Напиши простой тест для проверки race condition
   - Создай скрипт для ручного тестирования (curl с параллельными запросами)
